## Search and dataset navigation

The Investigator has two explicit modes. Basic is the default for a new visit: it accepts one Stellar G-address, fixes direction to both and depth to one, and does not retain hidden advanced filters. It presents a three-state directory assessment derived only from public directory metadata: `Trusted` requires a verified identity without an adverse label, `Untrusted` requires an explicit adverse label, and `Unverified` covers all inconclusive or unavailable metadata. The assessment is not a safety certification or fraud determination, an unlisted account is never automatically `Untrusted`, and a visible `Not a guarantee` note tells the user to confirm the full address independently. Indexed payment patterns remain separate evidence and never change the assessment. The loaded state moves technical definitions to accessible tooltips, omits duplicate event/transaction cards, hides account-context counts and exports, and presents two always-visible evidence surfaces: Payment details followed by Event timeline for this page. Advanced accepts an account or transaction hash and exposes direction, operation type, bounded hop depth, ledger/date bounds, exact asset and minimum-amount filters, complete page metadata, exports and the same two evidence surfaces. The selected mode is URL-backed; transaction targets always resolve to Advanced. Switching to Basic clears incompatible transaction input and all advanced filters.

Account or transaction target, direction, operation type, optional exact-asset filter, optional minimum amount, ledger/date bounds and cursor are URL-backed committed state. Asset keys use the exact canonical value displayed in evidence, and matching checks both source and destination assets in the event source. The positive minimum applies before the page limit; unknown amounts do not pass. Draft filter edits require Investigate. Changing committed filters drops the cursor. Page size is 50; order is ledger descending then event ID descending. Older pages replace the page, not append ambiguous totals. Latest page resets pagination. Back restores the prior URL/query. Clear cancels pending work, removes target and filters and focuses search.

The Q3 release does not expose an asset as the primary investigation target. The local API implementation for asset-only reads remains dormant until its additive side index is installed, populated and validated; no new historical backfill is part of this release. Asset filtering over an account or transaction remains available from existing indexed payment-flow data.

The public `/v1/trace/address/{id}` and investigation route share the classic payment-flow reader. Account targets may request depth 2 only with both ledger bounds or both UTC date bounds. Depth 2 expands a capped frontier over address-leading indexes, preserves event order and the asset at each hop boundary, and reports every cap/truncation. It describes candidate paths, never proof of funds continuity, ownership or control. Transaction targets remain depth 1; unsupported targets or unbounded depth 2 return typed 422 errors.

Graph, heuristics, grouped flow table, grouped transaction table and exports describe the current page only. The Investigator UI shows observed payment patterns without a numeric risk score; legacy `riskContext.score` and `level` remain in the API for compatibility and must not influence or be presented as the directory assessment. The evidence switch toggles grouped flows and individual events without changing the underlying page. Flow groups keep source and destination amounts in separate asset units; an unknown event amount makes that side's group total unknown. A transaction may span two pages; grouping never claims a complete transaction. JSON includes query/coverage; CSV repeats network, page scope and filter metadata. The standalone HTML report is print-ready, escapes all untrusted evidence and carries an explicit page-scope warning. Exported decimal and bigint values remain strings; CSV neutralizes spreadsheet formulas.

Account labels and verification badges may appear as directory context, but the separate account-metric payment counts and dates are not displayed beside historical payment-flow evidence: their retained-source coverage is different and a zero can contradict events on this page.

Counterparty cards link separately to the account detail and to a new one-hop Investigator search for that address. This is a manual pivot to a different page-scoped query, not a chained flow or multi-hop funding claim.

The case queue stores only a network, account/transaction identifier, watch flag and local save time. It does not store report content, notes or raw evidence; saved identifiers can still be sensitive. Watchlist means a local marker, not monitoring or notifications. The UI warns that anyone using the same browser profile can view saved targets, especially on shared devices. Queue entries for other networks remain in storage/export but are not opened on the current network. Import is explicit, validates every entry before merging, does not overwrite existing watch flags and is capped at 100 entries/128 KB. A corrupt or inaccessible stored queue disables writes to avoid accidental replacement; browser storage loss cannot be recovered unless the user exported a file.

Native XLM summaries in the cards, counterparty map and timeline display exact decimal strings; small nonzero payments must not be rounded to a visible zero. Both Investigator routes own the document title through Next.js route metadata, including after hydration.

## State and recovery

Initial search, pending, empty results, loaded data, validation errors and API errors are distinct. An empty filtered page says no indexed events match the target and selected filters; it does not claim that the target has no other activity. Submit is IME-safe, `noValidate` delegates errors to the app, and invalid submit focuses the first invalid field. Nonempty search has an explicit Clear action. AbortController plus stale guards prevent older requests replacing a new query; HTTP requests time out. Retry repeats the same committed query. Error text never exposes raw connection details.

Pagination and export are disabled while pending. No success notice is shown for unavailable data. The latest observed indexed ledger is explicitly not a contiguous-ingestion watermark. Heuristics are not verdicts. The public navigation and page heading use `Account Trust Checker`; its `Evidence-based` badge and visible scope warning prevent the marketing name from implying certification. Document title is `Account Trust Checker — StellarChain`.

## Verification and existing drift

Use targeted Node regression tests, TypeScript, changed-file ESLint, production build and browser smoke checks on desktop/mobile, light/dark, keyboard, loading, empty/error and success. No project-wide WCAG certification is implied. Canonical sibling: the Statistics page's client-only API and paginated dataset behavior.

This package retains established styles. Existing low-contrast muted text and unrelated routes lacking form contracts are migration debt, not newly accepted design rules. Static skill audit results are kept outside the source tree and reported separately from runtime evidence.

## Historical charts

The Statistics overview includes every enabled chart metric. Its `active-addresses` card shows only the latest five-minute distinct-source count when five-minute buckets are selected; for longer buckets it shows no numeric value and links to the five-minute chart. This is not a period-unique account count. The `output-value` card has no comparable total or trend because it mixes asset units, but still links to its audit page and page-scoped CSV. `max-fee` is the peak five-minute sum of fee limits in the selected range, not an individual transaction maximum. Contract cards are explicitly labeled as indexed detail-text matches, not complete verified creation/invocation totals.

`/chart` lists only metrics enabled by the backend catalog; `/chart/{slug}` uses the same `/v1/network-metrics` collection as external API clients. Metric, bucket size, page and optional `before` boundary are navigation state. Chart requests use `windowDays=30`: the API anchors the latest window to the latest indexed source bucket, aligns UTC boundaries to the selected bucket size, and returns an exclusive end plus older/newer window boundaries. Page totals and source choices apply only to this window; pagination never implies a verified gap-free chain interval. The selected source applies only to the displayed page. The chart converts decimal strings to floating-point for visual position and uses compact K/M/B formatting; CSV retains exact decimals and source provenance. Export is explicitly current-page only. Empty, pending and failed requests are distinct; old requests are aborted on navigation and retry preserves the current route. No gap filling or contiguous-history assertion is made. The public API requires `windowDays=1..30` and returns `422 window_required` when absent, so unbounded full-history aggregation is no longer available. Bounded-window grouped-count and resampling cost still require runtime validation against production-sized statistics before rollout.

Individual chart requests use 50 grouped rows per API page across all datasets. Bucket size, optional dataset and current-page CSV controls share a compact toolbar inside the chart card; the toolbar remains visible during pending and failed requests and wraps on narrow screens. The trend uses a fixed keyboard-focusable viewport rather than an internal browser scrollbar. Mouse drag, touch swipe, horizontal/Shift-wheel and arrow keys pan through loaded buckets in both directions. Reaching the older edge automatically requests the next real API page and, after the current 30-day window is exhausted, the preceding window; a centered overlay spinner preserves the plot geometry. Arrow keys provide the non-drag alternative without adding separate temporal-navigation buttons. Failed history loads preserve the chart and expose an inline retry.

Chart history accumulation is transient view state: it does not rewrite the route or export scope. The CSV remains tied to the current URL-backed API page, while chart metadata states the loaded and visible bucket counts. The individual chart page does not duplicate bucket rows in a table. Changing metric, network, bucket size, page or historical window aborts any edge request and resets accumulated chart history. Exact-value and provenance guarantees remain page-scoped.

Statistics overview cards with an enabled catalog metric link directly to that metric's `/chart/{slug}` page and carry the overview's selected bucket size. The card itself is a keyboard-accessible link with a visible destination cue; unknown future metric keys remain non-interactive rather than linking to an unavailable chart. The overview range does not change the chart page's separate 30-day window. `/chart` remains the complete catalog for metrics not shown as overview cards.

Each enabled metric has a separate static `/chart/{slug}` URL and SEO description, backed by one shared client component and a metric-definition catalog. The chart header's back control returns to `/statistics`, the owning overview where users enter individual metric charts. The catalog owns the value label, precise source-derived definition and interpretation caveat; page and CSV export carry that context. Export contains only the current API page's selected-source rows, never all sources when one is selected. Request-key gating prevents a previous metric/window response appearing briefly during navigation. Related charts link to distinct routes within the same metric family. `output-value` combines nominal amounts from different asset types, so the page exposes indexed values through the page-scoped CSV but suppresses the trend until asset-scoped values exist. `active-addresses` is available only at five-minute distinct-source grain; hour/day requests return 422 until period-unique identities can be rebuilt. `max-fee` currently stores sums of the Horizon `max_fee` field per five-minute bucket and resamples with `MAX`; it must not be called a per-transaction maximum. Contract creation/invocation counts are detail-text matches, not completeness claims.

Chart lines break when two adjacent displayed rows are separated by an unindexed bucket. The page labels only gaps detectable between the current viewport's selected-source rows; it makes no claim about the rest of the loaded history. Out-of-range API pages return no rows without executing a large OFFSET query and link back to the last valid page.

On chart request failure, Retry repeats the current request; Latest window clears a stale or malformed historical boundary so the user has an explicit recovery path.

The Statistics overview, chart catalog and individual chart routes use the same bordered explorer surfaces and compact heading hierarchy as ledger/transaction details. Chart axes and tooltips use UTC; subdaily ticks include a time, and the individual metric axis starts at zero. The API and page-scoped CSV retain `source` as provenance; when more than one source is returned, a dataset selector remains visible so rows are never silently combined. Statistics load failure shows a bounded Retry action and does not expose raw API error details.

Supplementary metric caveats and technical chart details use the shared `InfoTooltip` next to the relevant title or metadata. Tooltips open on hover, keyboard focus and activation, close with Escape, and contain no actions or essential navigation instructions. Page scope, gap warnings and pan-navigation instructions remain visible.

## Contract provenance and SAC comparison

SEP-55 build attestation, indexed/decompiled code availability and registry metadata are separate signals. A decompiler result must never set a build-verified badge. SEP-58 is draft and no reproducible-build claim is displayed until a rebuild has actually completed and matched bytes. SAC comparison uses seven-decimal raw units; non-integer or missing supply is unavailable rather than truncated. Soroban indexed holder balance and Horizon total asset supply have different scopes and observation times, so equality is not an expected invariant or a safety verdict.
