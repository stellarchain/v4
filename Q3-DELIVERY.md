- Investigator dust filter: optional positive `minAssetAmount` requires an exact asset key; source or destination amount in that asset must meet the threshold. Filtering happens before cursor pagination, and CSV/JSON/HTML exports carry the threshold. Unknown amounts do not pass. This remains a first-hop, address/transaction-focused query.
- Historical charts: `/chart` catalog and 21 individually described `/chart/{slug}` routes backed by one shared view and `/v1/network-metrics`, with bucket/page and bounded 30-day UTC-window navigation, a compact K/M/B value table, related-chart links and page-scoped exact-value CSV export carrying metric caveats. The mixed-asset `output-value` page suppresses its misleading trend. The public API now requires `windowDays=1..30`; missing it returns `422 window_required` before the reader runs. The reader interface also requires and validates that window, preventing an internal unbounded fallback. This is a deliberate breaking change from legacy unbounded reads.
- Chart lines now break at gaps between adjacent bucket rows on the selected page/source; the gap notice explicitly covers only that page. Out-of-range API pages skip the OFFSET query and link back to the last valid page; integer-overflow page input is rejected.
- Investigator counterparties offer a manual link to investigate that address in a fresh one-hop query, alongside the account-detail link. This does not assert a traced multi-hop path.
- `active-addresses` is restricted to its truthful five-minute distinct-source grain in both API and chart UI; requests for 60/1440-minute resampling return 422 instead of a misleading period-unique count.
- P0 local correction: the separate `/statistics` overview no longer exposes an averaged `active-addresses` range card. Contract creation/invocation cards say "matches" because they rely on indexed detail-text markers. Investigator no longer shows a numeric page-derived risk meter or account-level risk badge; the legacy API fields remain for compatibility with an explicit page-scope limitation.
- Investigator identity cards no longer juxtapose account-directory payment totals with historical payment-flow events; the two sources have different coverage, so a directory zero is not evidence of zero historical payments.
- Contract presentation: decompiled/indexed code no longer implies build verification; SEP-55 attestation is distinct from registry metadata, and SAC holder/supply comparison describes its non-parity scopes. No SEP-58 claim is displayed without a completed reproducible rebuild.

## Historical metric correction design (no production writes authorized)

- Keep the current `output-value` rows as legacy mixed-unit evidence; do not reinterpret or overwrite them. A corrected series needs a new asset-keyed grain, explicit choice of source versus destination amount for path payments, and a proven historical source. The existing scalar `network_metric_point` key alone cannot encode asset identity.
- Keep the current `max-fee` rows labeled as peak summed fee limits. A true maximum transaction fee limit needs `MAX(history_transactions.max_fee)` per source bucket, a new versioned metric key/table, and recomputation for the intended history. The stored sums are not invertible after Horizon history truncation. Do not silently switch the old key's meaning midway through forwardfill.
- The existing five-minute `active-addresses` values are valid at that grain only. A true hour/day distinct-source count needs account identity per period, not a sum/average of five-minute distinct counts. Build it from indexed transaction sources or a dedicated exact distinct-account aggregate after validating source availability and cost.
- `top-payers`/`top-receivers` need an asset-scoped, time-bounded ranked identity model; cross-asset nominal amounts must never be added. `top-contract-callers` needs independently indexed Soroban invocation identities and coverage. None belongs in `network_metric_point` as a scalar. Define coverage, tie order, pagination, indexes and a bounded rebuild before enabling those catalog keys.
